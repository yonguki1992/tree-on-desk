# 작업 기록

1. 배정 시 [카드 양식](../templates/TASK.json)을 tasks/<ID>.json으로 복사한다. 파일명과 id를 일치시키고 owner 한 명, 실제 변경 범위, 관찰 가능한 완료 조건을 적는다.
2. dependsOn에는 실제 선행 카드 ID를 넣는다. branch에는 실제 작업 브랜치를 기록한다. 미착수 카드는 빈 문자열을 쓸 수 있다.
3. 현재 상태는 카드의 status에서 읽는다. todo는 착수 전, in_progress는 진행 중, blocked는 진행 불가, review는 사용자 검토 대기, done은 완료 조건과 사용자 완료 판단을 확인한 상태다. PR을 사용하는 작업은 필요한 병합까지 확인한다.
4. evidence에 수행한 검증과 결과를 남긴다. blocked이면 handoff에 차단 사유와 재개 조건을 적는다.
5. [TODO](../TODO.md)에는 작업 순서와 카드 링크를 기록하고 우선순위가 바뀔 때 갱신한다. 상태 전환은 카드에서만 갱신한다.
6. 작업 종료 시 docs/handoffs/YYYY-MM-DD-<ID>-<agent>.md를 한국 날짜 기준으로 작성하고 카드의 handoff에 경로를 남긴다. 같은 날 같은 작업의 후속 기록은 -02처럼 구분한다. 스냅샷에는 기준 브랜치·커밋, 변경 범위, 검증, 열린 문제, 다음 행동, 해당하는 경우 PR 링크를 적는다.

핫픽스는 사용자가 지정한 시점에 HF<숫자 3자리> 카드로 등록한다. branch에는 원본 핫픽스 브랜치를, handoff에는 배포 버전·사유·기준 SHA·두 대상 PR·대체 PR과 통합 브랜치(해당 시)를 기록한다. [두 대상의 완료 조건](COLLABORATION.md)을 확인한다. 인수인계에는 [공통 양식](../templates/HANDOFF.md)을 사용한다.
