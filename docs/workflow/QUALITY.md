# 검증과 완료 기준

제품 검증 명령과 지원 환경은 [프로젝트 지침](../PROJECT.md)에 기록한다. 문서 변경은 상대 링크·경로·규칙 충돌을 확인한다. 코드 변경은 영향을 받는 정상·오류·경계 조건을 검사하고 배포 결함은 동일 환경에서 재검증한다. 릴리스는 실제 배포 형태에서 확인한 범위를 명시한다.

하네스 검증은 프로젝트 루트에서 실행한다.

```sh
node scripts/check-task-records.mjs
node --test scripts/check-task-records.test.mjs scripts/branch-guard.test.mjs
```

## 기록 형식

명령 / 실행 환경 / 성공·실패·미실행 / 요약 결과 / 미실행 이유. 새 실패를 숨기거나 실패 검사를 제거하지 않는다. 기존 실패는 재현 근거와 영향 범위를 분리한다.

## 완료 조건

요구사항 충족, 책임 분리, 경계 준수, 필요한 검증 성공 또는 제약의 명시, 새 모듈/계약 문서 갱신, 해당 task와 새 스냅샷 기록. Todo 변경은 계획이 바뀐 경우에만 필요하다. 미실행 검증이 핵심 동작을 막으면 blocked 또는 검토 대기로 남긴다.
